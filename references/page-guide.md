# 页面组织指南

这是一条推荐阅读顺序，根据项目和用户要求合并、调序或省略章节。同一信息集中说明一次，其他位置按需链接；不要把指南的解释或占位符搬进 README。

文案直接讲用途和操作。删除重复解释、显而易见的操作提示，以及不影响使用的小字注释；标题已说明“模板”或“示例”时，不再附一段同义说明。必要的来源、概念图身份、数据口径和使用限制就近简述，不能为简洁而隐去。

## 首屏：看懂并找到入口

名称 + 一句话用途 + 主要入口。有合适的 Logo、宣传图、真实界面或交付物时，精选代表素材放在开场或靠前的效果区，不全部堆放。品牌图负责介绍项目，效果示例负责解释能力，分别判断是否需要；没有合适图片的简单产品或 Skill 默认用精炼文字开场。文字无需为了居中而全部居中。

一句话尽量带具体动作和对象，例如“批量压缩图片，保留原始文件”。避免只有“强大、高效、一站式”。

主要入口通常是下载或安装，其次是教程和反馈。平台、最低系统要求、测试版状态会影响使用时，放在附近。徽章不单独开章，通常优先平台、版本和许可；Star 可选，构建状态仅在对读者有意义时放。

短页面可以不设目录；长页面可用少数重点跳转或折叠目录，不让目录挤走用途和效果展示。

## 效果：先看一个有代表性的结果

| 项目 | 优先展示 | 需要避免 |
| --- | --- | --- |
| 桌面或网页工具 | 主界面真实截图、一次核心操作演示 | 装饰大图挤走下载入口；用设计稿冒充真实产品 |
| 命令行工具或代码库 | 最短输入与实际输出，必要时配截图或有条件说明的性能图 | 只有一长串参数；没有来源的速度比较 |
| 单个 Skill | 用户输入、所需素材、最终交付物，适合时附产出截图 | 只展示 SKILL.md 或内部文件结构 |
| Skill 集合 | 按用途列出的 Skill 名称、作用与入口，精选代表案例 | 把所有 Skill 的完整教程堆在主页 |

有多份素材可选时，优先展示真实成品中能体现能力的内容页、核心界面或操作前后对照，避免只展示封面、标题页或空模板。已有演示可以直接截图，先确认画面完整、字体和资源已加载；模板截图仍标明模板身份，不当作真实客户成果。封面适合品牌介绍时可保留在开场，不能包办效果展示。

示例须区分实际运行结果与说明性示例。没有实测结果时，使用基于真实能力的示例请求并明确标识，不伪造对话或效果数据。

优先选一份能解释核心价值的素材，再按需补充；一句输入输出已能讲清时，不扩成一组截图。图片保留有意义的替代文字，图注只补充画面和标题没有说明的必要信息；动态图无法表达细节时，补静态结果或视频入口。缺图时先用有依据的文字示例，需要补图就在交付说明中列出。

## 用途：让读者判断是否适合自己

挑最关键的几项功能，用“动作 + 结果”表达。有明显适用人群或前提时就写清楚，简单项目可并入简介，不单开“适用人群”。

文件夹结构仅在用户需要定位、配置或扩展文件时展示；实现原理按理解成本决定是否放入独立文档。

## 开始：从准备到第一次完成

按真实顺序写清：提供什么 → 选择或操作什么 → 确认什么（如有）→ 得到什么。保留选项、按钮、模式的正式名称与编号，用短句解释；涉及选择时给一个与实际流程对应的例子。

### 工具、应用或代码库

1. 使用前提：支持的平台、必要账号或依赖；存在服务费用、联网要求或重要权限时准确说明。
2. 首选安装方式：给实际下载入口或核对过的命令。其他方式多时折叠或链接到独立教程。
3. 首次操作：按用户实际点击或执行的顺序写，提供最小必要输入。
4. 预期结果：告诉用户会看到什么、文件保存在哪里或怎样判断成功。

有成品下载的应用优先介绍成品；源码构建放在后面。代码库补一个最小调用例子。

### 单个 Skill

1. 简述所需 Agent 能力和必要工具；若支持自带工具与外接 API，清楚列出两条使用方式，不展开无关的环境差异。
2. 给真实可用的安装方式，区分单个 Skill 文件夹与整个仓库；具体路径依据目标 Agent 的实际规则。
3. 给一条可照着说的请求，说明用户要先提供哪些文件或信息。
4. 写清会交付什么、保存在哪里，以及完成后用户要做什么。

Skill 集合先帮助用户选中一个 Skill，再链接对应的安装和使用说明。

## 帮助与收尾

- FAQ：只补正文尚未回答、用户容易卡住的真实问题。
- 已知限制：影响使用决定的限制放安装前或对应步骤旁，其他限制放帮助区。
- 文档：链接文字写“安装教程”“进阶用法”等用途名称，不机械罗列目录中所有 Markdown 文件。
- 反馈与贡献：优先提供真实问题反馈入口，再链接参与开发的说明；无需为了这一章新建贡献文件。
- 开源许可：简短说明并链接实际许可。
- 额外声明：确有需要才写，明确所指对象，区分品牌名称、项目许可与生成作品归属，不套用含糊的权属声明。
- 更新、计划、赞助、致谢和多语言版本：按实际需要加入；未实现的计划与已有功能分开。

## 更新已有页面

功能变更时同步受影响的简介、截图说明、安装步骤与示例。整体装修优先复用已有品牌与素材。

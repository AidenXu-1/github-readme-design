# 视觉与成本指南

用于整体装修、首屏重设计与展示素材制作。页面顺序见 page-guide.md；这里仅决定视觉表达与投入。

## 先找到属于这个项目的表达

先盘点现有标志、配色、真实界面、演示与交付物。继承已确认的品牌，按 SKILL.md 的素材边界选择表达；需要调整布局或用户已要求新品牌视觉时，内部比较少量候选，用一句话说明选定方向与投入理由。除非用户要求，不先制作多套完整成品。

| 项目特点 | 可选表达 | 创意落点 |
| --- | --- | --- |
| 有可辨认的界面 | 产品展台 | 裁出核心操作，统一画面背景与标注 |
| 核心能力是转换或处理 | 输入输出对照 | 让同一份真实素材的变化可见 |
| 已有品牌素材，或用户明确要求新增品牌视觉 | 品牌主题 | 延续现有视觉；获准新创作时可结合项目意象，如连接工具的节点连线 |
| 无现成图片的简单产品或 Skill | 编辑式排版 | 名称、短句、层级和留白形成节奏，必要时用一条说明图 |

这些是思路，允许组合；不固定渐变、吉祥物或大横幅。借鉴案例的表达方法，不复制别人的品牌素材。插画与说明图不能代替真实效果证据；仅有项目名称或抽象意象，不构成新增品牌素材的理由。

## 集中做一处亮点

- 先选一个主要视觉焦点。大标志、宣传横幅、截图墙同时出现时，删掉重复表达的部分；主要开始入口不藏在大图后面。
- 从品牌提取主色，徽章和说明图沿用同一套颜色与图形语言。正文使用 GitHub 原生字体和标题层次；开场可以居中，长说明保持易读。
- 比较同类信息用表格，解释顺序或关系用简图，独立要点用短列表。不把整页做成图片，也不靠宽表格模拟多列网站。
- 图片按 README 实际显示宽度检查文字大小，裁掉无关留白与窗口区域；教程命令和关键信息保留可复制的文字。

## 按收益控制成本

成本同时包含制作时间、额外工具或服务费用、加载体积和后续修改。复用素材通常成本最低；在素材边界允许的范围内新增时，说明它能补足什么信息。

| 默认选择顺序 | 适用时机 | 控制方式 |
| --- | --- | --- |
| 现有素材与原生排版 | 已能清楚介绍项目 | 优先调整裁切、尺寸、顺序与短文案 |
| 一张简单说明图 | 真实流程或关系难以用短句解释 | 按需制作，保留可编辑源文件；不强制安装新工具 |
| 一段核心操作演示 | 有真实可操作的产品，且过程本身体现价值 | 优先复用已有演示；需新录制时在任务授权范围内进行，不模拟不存在的界面 |
| 新品牌主图、定制插画、多场景动画、独立演示站 | 用户明确要求制作 | 先说明新增工作与费用，在已授权预算内制作 |

默认先完成一版和一轮针对性调整；用户继续要求修改时继续。发现具体问题再迭代，避免仅为“再高级一点”无限生成。没有额度或价格依据时不承诺免费，也不自行启用额外付费服务。

本 Skill 的建议体积目标为单张静态主图约 500 KB 以内、首个 GIF 约 3 MB 以内，均非 GitHub 限制。清晰度优先，超出时检查裁切、压缩或改为静态图加视频链接，不为达标损坏可读性。静态品牌素材优先随仓库保存；动态统计按需使用，第三方装饰服务不承担唯一的名称、用途或安装入口。

## 符合 GitHub 的显示方式

- README 使用原生 Markdown 与简单 HTML；页面级脚本、自定义 CSS、交互组件放独立演示页。预览不要靠额外样式制造 GitHub 无法显示的效果。
- 标志和示意图可用作为图片引用的 SVG，截图用清晰的栅格图片。避免依赖外部字体、脚本或嵌入 HTML 的复杂 SVG；无法稳定显示时提供 PNG。简单流程可用 Mermaid，仍需核对 GitHub 显示。
- 优先让同一张图兼容深浅背景；确有需要再用 `<picture>` 提供深浅两版及默认图片，避免无意义地维护双份素材。
- 整体预览重点看：开场是否有主次、开始入口是否明显、手机宽度下是否能读、深浅背景是否清楚、动态图不播放时是否仍能理解。图片失效时，正文仍应说明用途和开始方式。

## 仓库主页的其他位置

用户要求整个仓库主页装修时，同时检查 About 简介、网站链接、Topics、Release 入口与分享预览图是否和 README 一致；只要求 README 时不扩展为设置改造。

分享图可复用主图构图，按 GitHub 当前要求导出；它需要单独设置，不会因添加 README 图片而自动生效。没有线上修改授权时只交付素材与设置建议。
